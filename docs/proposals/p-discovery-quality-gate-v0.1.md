# P Discovery — Quality Gate v0.1

**唯一目标：高质量发现可实现的可能性，而不是追求条目数量、模型速度或复杂的产品界面。**

## 1. 什么才算高质量 P Map

一个可发布的地图必须让初学者发现该主题下重要、真实、有用、可选的用途，同时清楚说明边界与证据。比较标准不是“回答里有多少行”，而是**与官方文档及独立评审相比，遗漏了多少重要可能性、有多少错误/重复/混淆、能否指出哪些功能需要扩展插件。**

优先级（高到低）：
1. **真实性**：不能把实现不了、没有依据或超出主题边界的条目标为已确认。
2. **覆盖与新发现**：不能只罗列最出名的 5–10 项而遗漏有价值的类别。
3. **合理粒度**：P 是可观察结果，不是 API 方法名、安装步骤、抽象概念；重复项少。
4. **选择价值**：新手读完，能提出先前不知道可以提的有效需求。
5. **表达与可用性**：用自然语言、简明类别、可检查来源解释；不要为了凑数制造深层树。

## 2. 双层门禁

### 自动门禁（可以在 CI 执行）

- `SKILL.md`、示例 JSON、Python 校验器能被标准环境读取。
- 结构合法、ID 唯一、分组及引用存在，扩展能力说明条件。
- `source_supported` / `reviewed` 每条 P 都有独立的 `evidence_refs`，引用的 `quote` 必须能够从对应 Source 的原始摘录中找到；不能仅放一个 URL。
- `reviewed` 需要人工审核记录；自动生成不得自称人工核实。
- 正反例测试必须覆盖：假引文、找不到的来源、断开的分类、未说明条件的扩展能力、无人工审核记录、可保留的 `proposed` 条目。
- Codex/OpenCode 项目目录可直接识别；Claude 项目安装后内容保持相同。

**自动门禁不验证外部网页的原文是否真正抓取，也不验证“引用语义”是否支持结果。** 因此，仅绿 CI 不能宣布 P Discovery 已经具备高质量发现能力。

### 人工内容门禁（决定是否能发布）

- 逐条打开最重要的原始出处，核对摘录、上下文、功能版本与插件归属。
- 独立制作一小份主题关键用途基准清单；对比 P Map 有没有漏掉主要能力。
- 做盲审：不给评审者看到模型预先写的“已验证”标记，让其判断是否真能从来源推断该能力。
- 让不熟悉领域的人先列出知道的用途，再使用地图；记录新增的真实可行用途，并检查是否能准确向 Agent 表述需求。
- 把错误、遗漏和反常输入记录为回归案例；每次改 Prompt 至少重跑原先失败的样本。

## 3. 评估数据与验收目标（研发目标，不是已达到的指标）

准备三个领域：`ggplot2`、`LangChain Agent`，以及一个**预留且此前未用于 Prompt 调参的不同领域**。

- **真实性红线**：在每个主题的正式人工抽检中，严重错误（编造能力、引用张冠李戴、扩展归属错误）为 0；发现一项，先修复再复测。无限主题无法保证世界范围零错误，目标仅是已验证样本的交付标准。
- **关键能力覆盖率**：独立审核建立该主题 10–30 个高价值用途（数量随领域实际情况调整），至少覆盖其中 90%，没有高重要度缺口；无法达到则不能以“完整”宣传。
- **去重与粒度**：正式审核样本中重复、无意义、拆得过细的条目占比低于 5%；对评价有争议的条目记录分歧。
- **选择价值**：评估用户使用前后新增的正确用途，而不只看是否喜欢分类界面；至少提供可复现的案例和真实失败案例。
- **可迁移性**：至少分别在 Codex、Claude Code、OpenCode 进行一次真实调用，核对技能被正确加载、来源并非虚构、输出遵守共同契约。仅测试复制目录不等于验证 Agent 行为。
- **稳健性**：同一主题在不同运行中需保持核心 P 以及来源支持的一致性；允许类别与表述不同，但不能出现相互矛盾的能力结论。

## 4. 第一轮实验计划

1. 先跑 **ggplot2**，不强制输出一百个 P。官方页面、Gallery、扩展生态三种来源缺一类时需报告覆盖缺口。
2. 审查虚构的能力、引用和插件边界；对漏掉的图形能力回到资料源补证据，而不是仅靠模型再想一批。
3. 用同一版 Skill 跑 **LangChain Agent**，检验 P 的粒度和范围能否迁移。
4. 只在前两项达到可接受门禁后，选择未见过的第三领域作留出测试。记录关键 P 覆盖、错误/重复、证据真实性、用户新增正确选择。
5. 最后再决定是否需要模板、C/O 图谱或独立软件产品。**没有内容质量证据，就不宣称成功。**

## 5. 如何操作

从 COP 仓库的实验分支打开 Codex，调用：

```text
$p-discovery ggplot2。请尽可能发现重要且真实可实现的可能性，区分 ggplot2 基础能力和扩展包能力。对每一项给出来源原文位置；没有依据就标待验证。不要为了数量牺牲质量。请保存 possibilities.md 与 possibilities.json 并运行校验。
```

生成结果的本地机器校验：

```bash
python3 .agents/skills/p-discovery/scripts/validate.py outputs/ggplot2/possibilities.json
python3 -m unittest discover -s .agents/skills/p-discovery/tests -v
```

以上指令是用户/Agent 执行步骤；仓库 PR 的代码与样本自动验证可以由 GitHub Actions 完成。首次真实 Skill 调用的输出及人工评分尚未完成，**不得把样本测试通过等同于完整 Skill 质量验证**。
