# Next.js 发现记录（补漏修订）

## 范围

面向独立开发者，目标是可交付的 Web 软件与商业成果。研究当前 App Router；分清 React、Next.js 与数据库/认证/CMS/模型/支付/托管等依赖。文档日期和模板栈不合并成一个 semver。前提是基本 Web/React 知识。

## 第一轮：未分类候选

初始读官方 overview、数据获取、表单、认证、BFF、metadata、部署和 Supabase 后先记录：数据页面、财务仪表板、表单工作流、账号/权限、API、营销/分享站、MDX 文档、CMS 站、多语言站、在线店铺、单次付款、SaaS 订阅、可安装/推送 PWA、离线访问、AI 聊天、静态/服务端部署。先记录可能成果，不按 API 或分组组织。

## 第二轮：实际应用与完整案例

### 官方 Dashboard App 课程

读了官方完整课程正文的应用说明和章节概览：目标成品是有公开主页、登录页、受保护仪表板，用户可以新增/编辑/删除发票，并配置 Postgres 数据库。课程讲数据库查询、搜索/分页、Server Actions 修改与缓存重验证、验证和认证。这直接支持“财务仪表板”这一有明确用户任务的结果。它依赖数据库和认证服务，不是框架空白项目自动提供。按来源引文额度，只摘录了其中新增/编辑/删除发票的短语；正文周边已一并核读。

### AI SDK Chatbot 开源应用

读 Chatbot 概览和架构全文。可见其基于 Next.js App Router，以 Route Handlers 接 AI SDK 和多个模型供应商，用户登录后聊天、恢复历史；模型回复流到 UI 后写入数据库，示例还可上传附件、分享聊天，并由对象存储保存文件。此结果需要 AI SDK、Auth.js、Postgres/ORM、模型供应商和 Blob 等外部依赖，且模型 token/API 会产生成本；没有把它误报成 Next.js 原生功能。只确认“可登录并保存会话的 AI 聊天应用”这个合并结果，没有把每个细节拆成小 P。

### 商业范例

Vercel Shop 实际页面说明 Shopify 负责目录、购物车、结账和客户账户，Next.js 是应用层，因此仅确认扩展商店前台。Next.js 仓库 Stripe README 说明完整 TypeScript 示例以 Server Component、Server Action、Route Handler 提供 Stripe Checkout、Payment Element、成功页和 webhook，并需要 Stripe dashboard 凭证。Vercel SaaS Starter 进一步列明 pricing 页、Stripe Checkout、登录用户 dashboard 和 Customer Portal 订阅管理，并同时依赖 Postgres/Drizzle/认证。单笔和订阅支付可以确认，但不能说 Next.js 自带支付。

## 第三轮：补漏与反例检查

- **CMS/编辑出版**：重新走 Sanity 官方 Next.js 文档入口（不是先前 404 的旧短链接），正文说明结构化内容后台、可定制编辑环境、`next-sanity`、嵌入 Studio 和编辑/实时内容工作流；CMS 站现升级为 source_supported。
- **MDX 出版**：查当前 App Router 官方 MDX 指南，确认本地/远程 MDX 会转成路由页面、可嵌 React 组件；作为插件式本地文档/博客工作流单列。明确其不是面向非技术编辑者的 CMS。
- **多语言**：官方 App Router 国际化指南直接说明 locale 路由和页面内容，支持多语言站；翻译文字属于作者/项目提供，不归框架提供。
- **PWA/手机**：官方指南明确 Manifest、Service Worker、主屏安装、Web Push 与 HTTPS/VAPID 等条件；因此确认可安装/推送 PWA。对离线访问特别核对：Next 文档把 Serwist 作为扩展选择并提示 webpack 要求，故不把离线说成核心，也未单独提升为 P。
- **仪表板别名**：检查 nx-02，数据页面本身不保证图表、筛选、账号或仪表板产品，因此移除“仪表板”别名；改用实际课程证据新增 nx-13。
- **表单范围**：原 nx-03 的预约/留言举例没有单独案例证据，删除具体业务例子，仅表述服务端接收表单提交；明确真实业务仍需应用实现。
- **支付/CMS 路径重试**：Stripe 官方 Next.js README、新的 Vercel SaaS starter 成功提供具体支付和订阅实现；Sanity 作者官方集成文档解决了此前模板 404。保留逐条历史失败记录，不复用失败路径的时间/哈希。

## 归一化与分组

15 项确认结果按最终用户任务分组，而非按包名：内容发布、数据应用、外部系统、收款经营、移动访问、部署交付。合并泛化/重叠候选，去掉宽泛“Next.js 可造全栈应用”单条；拆分本地 MDX 作者工作流与 CMS 编辑工作流、单次收款与订阅，因为它们依赖不同服务和交付过程。删除数据页的仪表板别名。无确认条目自授 reviewed。

结果视角看完官方主指南；案例视角覆盖官方全栈财务应用和 AI SDK 完整聊天应用；扩展视角核对 CMS、MDX、i18n、PWA、Stripe、Shopify、Supabase 与 AI SDK。补漏后新来源补入了国际化、可安装推送、编辑内容、MDX、财务发票应用、AI 聊天和支付/订阅。已通过每个此前不足的能力家族新增独立来源路径。对最后一轮候选（离线缓存、原生移动、自动翻译、CMS 特定供应商替代、更多支付流程）再查时，可证能力已落在已确认结果或平台服务范围，不需要继续拆分；离线被明确边界为扩展/未确认。停止是因为成果类别和依赖边界已有直接来源、再加来源主要是重复集成选择，而不是为满足数量。
