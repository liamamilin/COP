# Bitwarden 发现记录

范围来自 catalog：密码库、自动填写、共享、账户恢复；需明确方案、客户端、云与自托管边界。

## 无分类候选（依发现顺序）

1. 在匹配网站自动填写已保存账户资料（结果视角，浏览器扩展）
2. 从应用内生成强密码/用户名并保存新账户（完整操作视角）
3. 用 vault health 找出重复、弱或泄露密码并改换（结果视角）
4. 创建有期限/隐私选项的 Send 分享敏感文本或文件（交付视角）
5. 通过组织 collection 与家人/小团队共享凭据（协作视角）
6. 导入其他密码管理器资料、加密导出 vault 作迁移/备份（迁移/恢复视角）
7. 预设 trusted emergency contact，用户无法响应时可读或接管 vault（个人连续性）
8. 由管理员恢复已加入 Enterprise recovery 的成员账户（业务恢复）
9. 选择 Bitwarden cloud 或自建 Lite/服务器部署（扩展/部署视角）
10. 普通用户忘记 master password 后由服务商重置（核验后发现不可行；不作为 P）
11. 自托管报告中的 Data Breach 报告可能需外部 HIBP API key（边界候选）

## 三轮发现

- **结果视角：** 官方帮助页演示保存的 URI 与当前站点匹配后填表；内建生成器支持在新建登录流程生成密码；Send 支持敏感文本/文件的临时链接；组织 collection 管理共享条目权限。
- **完整任务视角：** 对照导入和导出文档，形成从其他管理器迁移、或安全导出备份的连续结果，保留明文临时文件、重复项、Trash/Send、个人库与组织库的边界。对报告结果，区分客户端本地弱/重复检测和查询外部泄露库的路径。
- **扩展/恢复视角：** 对照 Premium 紧急联系人、Enterprise account recovery 和自托管 Lite；区分个人无法由 Bitwarden 重置的主密码、预先授权的个人接管机制，以及组织管理员依策略重设成员凭据的机制。核对 cloud/self-host 用户运维差异。

## 归一化与补漏

自动填充、生成强凭据与保存新账户是紧密但有不同目的的结果，分别保留；多种键盘/上下文菜单/内联菜单操作合并为自动填写能力。Vault health 报告合并为一个“找出高风险密码并更换”结果。Send 的限时文本/文件是对外分享，与组织内共享条目不同。迁移与导出并成可移入/导出 vault 的可迁移性结果，交代格式/数据限制。紧急联系人与管理员恢复按个人和组织权限区分。自托管具有实质的运维结果和门槛，故单列而不泛称安装插件。

## 未采用和未知项

未把 TOTP、passkeys、SSH key、CLI 和每一种客户端菜单另作 P，避免退化成节点/功能清单；本轮没有取得足够上下文做客户端逐项差异覆盖。Bitwarden Send 的加密分享由服务页面描述，但未运行真实收件人交付。产品方案页抓取用于套餐背景，P 中仅在帮助文档清楚说明时写限制，不引用浮动价格；不推断地区可用性。Self-host 中普通部署需中级至高级运维；不承诺自建能自动得到云服务的可用性或支持。自托管 Data Breach 报告有外部 API key 条件，此方向未升级为独立 P。

普通个人用户忘记主密码并无服务商恢复路径。登录仍存在的会话、提示、已登记紧急联系人或合资格组织恢复可作为预先安排/剩余途径；删除账户是永久操作，不能视作恢复办法。

## 停止依据

从官方 Help Center 读取了各任务的完整上下文，并补充了方案对照页与部署帮助页。范围内账户填充、凭据生成、健康检查、临时分享、团队共享、迁移、个人/组织恢复及云/自托管均有直接文档描述。产品有更多客户端方法和 2FA 细节；本轮以用户结果合并，而不是逐个菜单枚举。没有运行软件、做兼容测试、比价或验证自托管。
