# PostHog P Discovery 研究日志

- 日期：2026-11-05（UTC 抓取时间见 source-coverage.json）
- 受众：个人开发者、独立经营者；用于观察产品行为、收集反馈、检验改动和定位问题。
- 范围：PostHog 官方产品（Product Analytics、Web Analytics、Session Replay、Surveys、Feature Flags、Experiments、Error Tracking、Data Warehouse、AI Observability）；区分外部 SDK、MCP/脚本访问面及连接数据源。
- 版本：以抓取当天文档表述为准；未锁定 SDK/服务端版本。
- 未安装 SDK、未接入真实项目、未访问真实用户事件或账号。

## 第一轮：结果视角（未分类，按发现顺序）

1. 查看网站访客、页面、会话、跳出率和来源。
2. 发现用户从访问到注册/购买的流失步骤。
3. 对比产品使用趋势、留存、路径和高频行为。
4. 检查具体用户在关键转化流程中的会话回放。
5. 向特定用户收集 NPS、流失原因或开放反馈。
6. 查看异常发生在哪些用户、页面和事件附近。
7. 按用户属性或百分比分批开放和关闭功能。
8. 用随机对照比较新改动与旧版本的指标。
9. 把订阅、CRM 等业务表和产品事件放在一起查。
10. 检查 AI 请求的提示、回答、token 成本和延迟。
11. 把漏斗退出者做成再营销名单（需要外部目的地和适当合规处理，未验证实际连接效果）。
12. 从分析结果自动生成可执行产品建议（意向过宽，须有独立验证）。

## 第二轮：实例视角（未分类，按实例阅读顺序）

1. 官方会话回放教程展示从漏斗完成/流失人数下钻到用户和相关录制。
2. 官方 YC 客户故事描述产品分析仪表板与共同创始人匹配实验；案例报告 6 周组发送消息和被接受请求的差异，也称某项被请求的功能实验中无人使用。属于厂商发布的单一客户自述，不是独立审计。
3. 官方教程说明路径图和趋势图中的用户可关联到个体录制，提示聚合数据与单次行为需结合解读。
4. 没找到足够独立的个人经营者项目公开证据；此视角主要依赖官方教程和官方客户故事。

## 第三轮：扩展视角（未分类，按新增来源顺序）

1. Warehouse 可同步 Stripe、Postgres、Salesforce、HubSpot 等业务来源，或读对象存储/文件，并与产品事件 SQL 联查；这依赖外部账号/文件和定期同步。
2. AI Observability 可接收 SDK 采集的 traces，也可转发 Helicone、Langfuse、Traceloop、Keywords AI 已采集的 traces；此处标为扩展/集成依赖。
3. Surveys 通过应用 SDK 显示并采集回答；回答成为事件，可进一步查询或送至 Slack/webhook。没有把 Slack/webhook 的外部自动化冒充为 PostHog 核心应用结果。
4. Feature flags 用 SDK 在运行时解析，实验复用旗标和已有事件/仓库表指标；基础旗标/实验是 PostHog 功能，MCP/API 是管理入口，并不代替应用接入。
5. 页面列出各产品免费额度和按量计费规则，额度随产品类型变化；以真实使用当天 pricing 页面为准。

## 去重、归一化与补漏（之后分类）

- 将“趋势/仪表盘/留存/漏斗”合并成“分析产品使用、转化与留存”，避免将图表类型拆成细碎 P。
- 将“流失用户回放”“路径回放”“相关事件录制”归一到“检查转化漏斗中用户停滞的过程”；回放证据支持提出调查假设，不代表从回放中证明因果。
- 将“新功能开关/灰度/紧急关闭”归一到按条件逐步发布或关闭功能。
- 将实验统计与观察性分析分开：前者随机分配变体并比较控制组，后者报告事件关联指标。即使是实验也需评估样本、方案、污染和统计不确定性。
- 将 AI 可观测性与普通事件分析区分，并注明 SDK 包装、转发或反馈采集依赖。
- 将“调出可导出用户名单用于触达”和“自动生成产品建议”暂留 proposed：读取到的页面不足以支撑完整用户结果、下游传输和有效性。
- 最终按用户目的分类：访问来源、使用与反馈、发布/实验、可靠性、业务/AI 运营。

## 父审查修订（2026-11-05）

- 删除“从真实案例中看到实验结果如何被使用”这一非用户任务 P；将 YC 的具体报告并入随机对照实验 P 的补充来源和案例说明。该报告是单一客户自述，不代表保证可复现 40% 增长。
- 收窄产品分析结果为观察采用、转化和留存，不再承诺同一 P 一并覆盖路径、粘性、生命周期、仪表板和告警。
- 收窄流量分析结果为查看来源与会话/跳出/热门页面指标；广告成本需接入广告平台，不把关联归因说成渠道增量。
- 每项已确认结果现在都有对应实际摘录和上下文位置；事件 SDK 采集与回放隐私遮罩用同主题补充文档支持。
- 补漏回查了 Web Analytics 定期摘要、仓库 SQL/文件、cohort 目标受众和 SDK/API 事件采集。定期摘要虽已在页面发现，但没有纳入当前 P，避免与流量测量混为一项；cohort、事件参考页及首页仅作为探索性背景来源列在 coverage，不充当 P 的已确认引文。导出和触达的完整个人经营结果仍缺少强证据。
