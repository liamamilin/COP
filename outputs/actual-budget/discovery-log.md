## 未分类发现顺序

1. 结果视角：只分配已有资金到预算类别；延续未用类别余额；在不同账户记录收支与余额；导入银行文件或手动记账；用账单对照交易；按历史行为自动归类新交易；提前排定重复收入/支出；比较期间开销和所有账户净值变化。
2. 完整任务视角：实际阅读 Starting Fresh 与 Envelope Budgeting 完整指导。候选包含选取账户、设置起始余额、导入/逐笔录入、建立分类、分配收入、在超支时调整和留存不定期开销资金。将目标收窄到有直观可验证的具体输出；没有把教程的储蓄、债务、退休等建议写成个人理财结论。
3. 扩展/部署视角：optional bank sync 要求服务商 API credentials 和 actual-server；页面列出 Akahu（NZ）、Enable Banking（欧洲）、GoCardless（欧洲但不接受新账户）、SimpleFIN（北美）、Pluggy.ai（巴西）。其他官方 getting-started 页面另强调 GoCardless 已停止接受新账户、SimpleFIN 的 US/Canada 覆盖。服务器数据库内的 bank-sync tokens 不受预算数据 E2E 加密保护。纯浏览器本地模式没有同步/自动保存/备份，需用户手工保存。

## 去重、归一化与最终分组

- 将每笔资金的预算分配、已有类别余额结转分成两个用户结果；不把 UI 点击或字段/API 当作独立能力。
- 将文件导入/手工交易输入写在同一记账结果中，另把对账单核对作为单独结果，因为它解决的是账簿是否与银行记录相符。
- 交易规则只保留可观察的 payee 清理和新交易自动分类，不扩写为完全自动理账。
- 计划收支是预期交易记录；不声称 Actual 代付账单或确保工资到账。
- 支出与净值报表作为描述性观察，不写成理财建议或因果分析。
- 银行连接单列为可选外部集成，列供应商地区/服务状态、actual-server、用户自行申请 credentials、token 暴露边界与 provider/hosting 费用未知。
- 纯浏览器本地使用单列为部署路径，其手动保存与数据丢失风险明确呈现。
- 分类在发现和去重之后完成。
