# Zotero 发现记录

范围来自 catalog：资料收集、阅读标注、引用和协作；区分原生、第三方插件、出版物访问与存储服务。

## 无分类候选（按发现顺序）

1. 浏览器一键保存当前网页为资料库条目（结果视角，Connector）
2. 整理 PDF 高亮/标注并回到原文页核对（结果视角，PDF Reader）
3. 将 PDF 标注汇编成带来源引文的笔记（完整操作视角，PDF Reader）
4. 从 Zotero 库选择文献插入 Google Docs 并生成格式化参考书目（结果视角，Google Docs 文档）
5. 与研究伙伴共享组库，并管理查看/编辑/文件权限（完整功能边界视角，Groups）
6. 在不同电脑同步条目、笔记、链接、标签（结果视角，Sync）
7. 另行同步 PDF、图像与网页快照文件（结果视角，Sync/Storage）
8. 用 Connector 导入 RIS/Refer 文献导出、自动代理跳转（扩展视角；connector 文档有说明但未单列P以避免拆分）
9. 用第三方插件处理某一特定来源类型或自动化任务（扩展视角；缺具体维护和任务案例）

## 三轮发现

- **结果视角：** 官方文档中 Connector 可保存网站；内置 PDF Reader 支持标注、回链及笔记；Google Docs/Word/LibreOffice 可插入文内引文和 bibliography；Group Library 用于共同维护资料。
- **完整案例视角：** 以官方给出的从文献库向 Google Docs 插入引用、刷新元数据、最后生成参考书目的写作流程核对上下文。PDF 标注可整理为单篇或跨文献笔记。团队工作流需明确组库与个人库分开、共享权限由组管理员控制。
- **扩展视角：** 对照 Zotero Connector、文字处理器集成、Zotero Storage 与 WebDAV；把浏览器插件和云附件同步标为 extension。未把出版商全文访问误算作 Zotero 的功能。

## 归一化与补漏

将网页收集、PDF 阅读/笔记、文字处理器引文、组协作、元数据同步与附件同步分开，因为各自产生不同结果和依赖。标注生成研究笔记仍归入 PDF 阅读结果，不再拆每种高亮颜色/注释动作。数据同步与附件同步明确分离，避免把本地 PDF/快照误称作已随条目同步。

补漏核查了在线目录的代理访问、RIS/Refer 导入、组权限、WebDAV、Storage 和附件访问。connector 提供代理检测，但真正出版物访问仍要求用户所属机构可访问；本轮不把它写成解锁付费全文。官方提及 add-on 和 Connector，但没有核验具体第三方插件的当前维护状态。

## 保留的未知项

- 未使用 Zotero 的浏览器 Connector 或 Word Processor Integration；Google Docs 会请求对目标文档的读取/编辑权限，未实际验证该授权流程。
- 未实测 groups 权限组合、所有者离组/账户恢复或组织组存储用量。
- Storage 价格、地区付款、当前配额和 WebDAV 服务兼容性未作现价核对；保留为需用户检查的服务边界。
- 网站 translator 的识别覆盖不保证每个出版商页面都能正确抓取元数据；具体期刊访问/下载仍受订阅和授权限制。
- 未找到合适的第三方作者 add-on 案例；扩展机制留在 coverage gap，不生成泛化 P。

## 停止依据

官方文档已分别给出收集、标注、引用、组协作、数据同步、附件同步的端到端动作与权限/存储限制。所要求范围的每个结果都有直接官方说明；额外搜索到的 Connector 子功能可记录为候选，但拆开会过细且不改变本轮用户结果。插件/地区价格/站点 translator 可靠性没有充分可复核证据，留为未知，不按覆盖穷尽处理。

## 第二轮扩展发现（审查后）

### 新增无分类候选，按此次发现顺序

10. 按项目/主题用集合和标签整理条目；同一条目可归多个集合。（结果视角）
11. 保存搜索自动囊括符合条件的新条目，可用于待读/状态清单。（结果视角）
12. 在资料库内查找并合并重复条目，保留集合/标签关联。（结果视角）
13. 在 Word、LibreOffice、Google Docs 插入动态引文与参考书目。（完整写作流程）
14. 从 Mendeley 在线库导入资料和文件夹结构；群组库、Mendeley Cite 和字段存在限制。（迁移案例）
15. EndNote 先导出 XML 再导入，需留意附件相对目录与未知字段；其他工具可用标准交换格式。（迁移视角）
16. Better BibTeX 面向 LaTeX/Markdown 使用者，在 Zotero 集合变化时自动导出文献文件。（具名扩展作者文档）
17. 合并条目同步保住格式化引用关联。（作为去重结果的边界，不另拆P）
18. 将元数据与附件同步作为同一跨设备文献访问结果呈现，同时明确它们需要分别配置、附件需要 Storage/WebDAV。（结果视角）

### 三轮补充发现与归一化

- **结果视角补漏：** 官方集合/标签文档直接说明多集合归档不复制条目、标签过滤和保存搜索动态更新；重复项文档说明识别范围、合并方式及保留关联。将整理和查重列为不同用户结果，因为前者组织检索、后者清理重复记录。
- **完整案例视角补漏：** Word Processor Integration 页面明确列出 Word、LibreOffice 与 Google Docs 的动态书目写作路线及插件安装方式，故合并首轮 Google Docs 单一路线为跨文字处理器的一个结果。EndNote 和 Mendeley 官方迁移说明补足文件夹/附件/字段限制。
- **扩展视角补漏：** Better BibTeX 作者文档给出针对文本化写作的具名任务和集合变化自动导出。它是扩展工作流而非核心能力；文档同时披露 Zotero 8 原生引用键变化以及旧版本维护边界。
- **去重归一：** 首轮元数据同步与文件同步分别是设置路线，但统一为“跨设备访问文献及附件”的用户结果，并保留两类同步不能混同的限制。新旧 Google Docs 文档信息合并进通用插件说明。迁移的 Mendeley/EndNote/标准格式流程汇成迁移结果，避免按每个格式拆碎P。

### 未采用和未知项

RIS/Refer 浏览器导入、代理跳转、保存搜索之外的搜索操作、WebDAV 配置细节没有拆为独立结果；属于流程组件或过细操作。Mendeley 在线导入依赖用户数据先同步到其云端；EndNote XML 中不支持的字段转成附属 note，需检查。Better BibTeX 文档提醒其 Zotero 7 支持不再更新；本研究没有安装测试。Storage 配额/现价、付款地区、WebDAV 服务质量、不同站点抓取质量和扩展安全性未核实。
