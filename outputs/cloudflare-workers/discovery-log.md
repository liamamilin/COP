# Cloudflare Workers Discovery Log

## 范围与顺序

研究个人开发者用 Workers 交付网站、应用后端和自动化服务，并区分核心 Worker 与平台组件/外部服务。先无分类收集候选，再检视完整教程和扩展组件，最后归并分类。来源取回日期为 2026-11-05。

## 结果视角：无分类候选

- 运行 API 与请求处理服务。
- 将静态前端与动态 Worker/API 一起部署。
- 提供有持久状态的用户待办清单。
- 为业务应用查询 SQL 数据库。
- 收集联系表单并写入第三方 Airtable。
- 运行实时多人聊天室并保留历史。
- 缓冲请求后续异步任务。
- 执行可暂停、重试的长时间多步骤工作流。
- 读写应用对象/媒体文件。
- 调用托管模型推理。
- 部署有持久身份、状态与实时连接的 AI Agent。

## 案例视角

Workers 官方 todo-list 教程把列表数据存入 KV，验证了可交付的用户清单应用。实时聊天教程实际部署聊天室，用户连接 WebSocket、群发消息并保存聊天历史。React SPA + API 教程让前端调用同一应用的 API Worker。Airtable 表单教程收集联系人字段并异步保存到 Airtable。D1 教程创建 SQLite 语义数据库和 Worker binding，最终部署可查询数据库的 Worker。这些教程说明各自先决条件，但本次没有执行/部署。

## 扩展视角与补漏

R2 官方使用指南补充 Worker 文件读写能力，需单独 bucket 与 binding。Durable Objects 的协调/持久状态通过实时聊天案例具体落地。Queues 处理消息缓冲/异步卸载，Workflows 处理有持久状态和重试的多步过程，两者成果不同。Workers AI 提供托管模型推理；Agents SDK 是基于 Durable Objects 等能力的独立方案，不能说是裸 Worker 默认功能。文档索引包含 framework guides、examples 和 tutorials；Hono 属第三方框架，未拆成独立结果。

检索国际化、CMS/MDX、PWA/离线、认证与支付方向时，没有取得能直接证明这些完整成果的案例，故未确认。

## 归一化与分类

合并重复的静态资产/应用发布描述，并将协调状态归并到实时聊天室。最终形成 11 项，按可见结果而不是按 API 名称归入发布网站与服务、保存和读取应用数据、连接外部服务、实时互动、后台与长流程、AI 应用。没有为增加数量拆分操作步骤。

## 覆盖缺口与停止依据

本轮覆盖官方入口、运行/产品手册、完整应用教程、扩展组件文档与第三方集成教程。补充索引和应用案例后，新资料主要支持已有候选；其余 CMS、国际化、离线、认证支付方向仍缺可靠案例。未证实这些事做不到，仅将其列为资料缺口。少数猜测 URL 404 记录在 source-coverage.json；成功响应都有实际时间、最终地址、类型与原始 HTTP 字节哈希。没有安装或运行代码，也没有测试性能、地区、费用与生产安全。
